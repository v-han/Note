# 介绍
使用隐式规则可以简化Makefile文件的编写。
有一些常用的、使用频率很高的东西，即使不在Makefile文件中编写，make也会自动推导出这些规则。
# 规则
一个简单的例子：
```Makefile
test : 1.o 2.o
	cc -o test 1.o 2.o
```

在这个Makefile中并没有写如何生成`1.o`和`2.o`这两个目标的规则和命令，但是make的隐式规则会为我们自动推导这两个目标的依赖目标和生成命令。

make会在自己的"隐含规则"库中寻找可以使用的规则，如果找到就使用，否则报错。在上面的例子中，相当于make生成了以下的文件：
```Makefile
1.o : 1.c
	cc -c 1.c
2.o : 2.c
	cc -c 2.c
```

在make的"隐含规则"库中，每一条规则都有对应的顺序，越靠前的是经常被使用的。
因此会出现以下的情况：
```Makefile
1.o : 1.p
```

这种情况下可能会对`1.p`(Pascal程序源文件)产生影响：

如果目录下存在`1.c`文件，那隐式规则一样会生效：通过`1.c`生成`1.o`文件。因为隐式规则中Pascal的规则出现在C的规则后。
## 常见的隐式规则
1. C程序的隐式规则：
	`*.o`的目标的依赖目标会自动推导为`*.c`，并提供`cc -c *.c`的生成命令。
2. C++程序的隐含规则：
	`*.o`的目标的依赖目标会自动推导为`*.cc`或`*.cpp`，并提供`cXX -c *.cpp`的生成命令。
